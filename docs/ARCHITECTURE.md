## الوحدات
| الوحدة | المسؤولية |
|---|---|
| `core` | الوسائط (فحص، تجريد EXIF، تصغير، طمس)، سجل التغييرات (append-only + trigger)، الإعدادات القابلة للضبط، التكرار الآمن (Idempotency)، النسخ الاحتياطي، أوامر الإدارة |
| `accounts` | المستخدم، رمز الدخول OTP، الأدوار مع نطاق المنطقة/الجهة، الجلسات، حذف الحساب |

| `agencies` | الجهات، قواعد الاختصاص (منطقة/مدينة × فئة)، تنبيهات الجهات، دليل الخدمات |
| `reports` | البلاغ وحالاته الأربع عشرة (`workflow.py` هو المكان الوحيد لتغيير الحالة)، التوجيه، الأولوية، التشابه، الإثبات والتحقق المستقل، الاعتراض، الرجوع، المراجعات اللاحقة، الحزم |
| `roadnow` | تنبيهات الطريق المؤقتة وقواعد صلاحيتها |
| `community` | المبادرات، الاحتياجات و«شن ناقص؟»، عروض المساعدة، المهام والحجوزات، المهارات والترشيح، نقاط العناية، الميزانية التشاركية، الفائض، تغطية المناطق والمسوح |
| `inventory` | مخزن الخير بأقفال صفوف (`SELECT … FOR UPDATE`) وقيد «لا تجاوز للكمية» في القاعدة |
| `finance` | التعهدات، الدفعات، أحداث المزود (فريدة)، مطابقة التحويلات، الصرف بفصل الصلاحيات، الاسترداد، السجل غير القابل للتعديل |

| `ai` | اقتراحات استشارية فقط؛ لا تستورد workflow ولا المالية (مختبر) |

## قرارات رئيسية وأسبابها
1. **Django + DRF + PostGIS** كما في المقترح: الاستعلامات المكانية (الاحتواء، المسافة بالأمتار عبر `geography`) تتم في القاعدة.
2. **حالة البلاغ لا تتغير إلا عبر `workflow.transition`**: جدول انتقالات صريح، كل انتقال له فئات منفذين مسموحة، ويُعاد التحقق من الدور والنطاق داخل القفل. لا يوجد منفذ «نظام» قادر على الإغلاق.
3. **التكرار الآمن**: `client_id` فريد لكل مستخدم + رأس `Idempotency-Key` + قفل استشاري في PostgreSQL يسلسل المحاولات المتزامنة لنفس المفتاح، فيعيد الطلب الثاني الاستجابة الأولى بدل خطأ.
4. **السجلات الحساسة append-only على مستويين**: حماية في النموذج + Trigger في PostgreSQL يمنع UPDATE/DELETE على `finance_ledgerentry` و`core_auditlog`.
5. **الخصوصية افتراضيًا**: الوسائط خاصة حتى يعتمدها مراجع؛ الوصف العام يظهر بعد التوثيق ومع حجب الأرقام/الأسماء؛ هوية المبلّغ لا تُسلسَل للعامة أبدًا.
6. **الدفع**: ثلاثة أوضاع (`disabled` افتراضي الإنتاج، `simulated` للتطوير، `live` يتطلب 4 شروط بينها تفويض صريح). المحاكي يوقّع الإشعارات كمزود حقيقي، وكل قيد ناتج عنه معلّم `is_simulated`.
7. **الويب كواجهة واحدة متعددة الأدوار**: المواطن والإدارة والجهات والميدان في تطبيق React واحد مقسّم كسولًا (lazy) — أبسط للصيانة، والصلاحيات تُفرض على الخادم بكل الأحوال.
8. **الخرائط**: Leaflet/flutter_map مع بلاطات قابلة للضبط (`VITE_TILE_URL`, `AAWEN_TILES`) وطبقة حدود المناطق من API الخاص بنا كي تبقى الخريطة مفهومة حتى إن تعذر خادم البلاطات.

## الافتراضات المسجّلة
- حدود المناطق في بيانات العرض **تقريبية** (مستطيلات) ومعلمة `approximate-demo`. الحدود الحقيقية تُستورد عبر `import_areas` من مصدر رسمي (بلدية/مصلحة التخطيط العمراني).
- أسماء الجهات في بيانات العرض افتراضية ومعلمة «(تجريبي)»؛ لا أرقام هواتف حقيقية.
- أرقام الطوارئ الرسمية **لا تُملأ تلقائيًا**؛ يدخلها المدير من مصدر رسمي متحقق.
- العملة الدينار الليبي (LYD)، المنطقة الزمنية `Africa/Tripoli`.
- أرقام الهواتف الليبية تُوحَّد إلى E.164 (`+2189XXXXXXXX`).
- الدخول للمواطنين برمز SMS؛ للفرق برمز SMS أو كلمة مرور يضعونها بأنفسهم (لا كلمات مرور افتراضية).
- التصعيد عند تأخر استلام الجهة (5 أيام افتراضيًا) **ينبه المنسق فقط** ولا يغير الحالة.
- الأولوية = خطورة الفئة (0–50) + خطر يقدّره المبلغ/المراجع (0–24) + قرب مدرسة/مستشفى (10) + العمر (حتى 10) + التكرار (حتى 10) + التأكيدات (لوغاريتمي، سقف 6).

## بدائل اعتُمدت بسبب البيئة
| المخطط | ما حدث | الأثر |
|---|---|---|
| Docker لتشغيل التطوير | سجل الصور محجوب → الخدمات شُغّلت مباشرة (PostgreSQL/PostGIS/Redis من apt) | ملفات Docker مكتوبة وصيغتها صالحة، لكن لم تُبنَ الصور هنا |
| بناء Flutter | Flutter/Dart غير متاحين ولا يمكن تنزيلهما | الكود مكتوب، **غير مبني وغير مختبر** |
| بلاطات الخريطة | خادم OSM غير متاح من البيئة | الخرائط في اللقطات تظهر بلا بلاطات (الحدود والعلامات تظهر) |
